对象是 `work_ooda/20261021-skill-cycle-v3/design-project-tests/scripts/validate_design.py:29` 的本地目录校验调用，不是 HTTP/RPS。负载单位是**每秒验证的三文档目录数**；p99/内存/吞吐目标及负责人均未签署，容量验收 BLOCK。

## 负载模型与工作负载

封闭循环仅适合限定 worker 的离线 CLI；若需要刻画新请求突发，另用定时 open-loop 发生器记录计划与实际发起数，避免 coordinated omission。混合合法文档、坏编码、缺评审，各占比由 owner 签署后冻结；合成文件只写独立空间，并比较失败分类而非仅测退出率。

## 环境数据与隔离

预置按 hash 冻结的三文档目录，只在专用空间测试，HOME/TMPDIR 和日志分开；禁止读写他人项目与共享服务。最大 worker、总调用数、RSS、文件数量和最长时间需要明确责任人签署；测试生成器不得与 CLI 争用同一配额而不另计资源。

## 观测与归因

同时记录目标已发起/完成/拒绝数、合法样本错拒与非法样本误放、p50/p95/p99 耗时、生成器 CPU 与磁盘竞争、fd/RSS/文件增长；冷缓存与热缓存分开，出现误放行优先按数据错误归因，不以零崩溃代替正确性。

## 停机回滚与恢复

只有在 owner 签署**数字**上限、杀停命令及测试进程列表后才允许注入负载。达到错误漏检、RSS、文件数、超时或磁盘预算任一硬上限即停止发生器，只终止本轮派生进程，保留 stderr、目录 hash 和时间线；确认原文件不变且冻结用例仍然可复现。当前值为 TBD，故所有压力例 BLOCK，不存在已运行或容量 PASS。

## 判据与报告

按真实发起/完成窗口及签署 SLO 比较、独立复算误放率，报告已批准的吞吐/尾延迟、负载发生器瓶颈、终止和恢复证据；签署缺失不得给容量合格结论。本设计 7 例全部 NOT-RUN。
