# r4 交接手册

## 可接收范围

本包对“开源搜索与静态首评 → 项目专属测试设计”的代码、文档、证据和维护流程做技术交接。接收者可不依赖旧服务器阅读材料、重放公共缓存、恢复冻结源码、运行本地回归及重新打包；真实联网搜索需要遵守站点规则，真实第三方执行另需批准。

“技术交接 READY”不等于人审签字、许可批准、真实项目质量或生产部署 PASS。后续有条件集成功能按各自门禁继续；不要求接手者相信历史全绿总结。

## 文件版本与回退

r5/r2 原包、冻结 r3 和旧真实测试FAIL账本不修改。r4 是新目录、新压缩包、新摘要。回退只切回保留的旧目录，禁止覆盖旧证据或将旧状态文件注入 r4。旧过程材料中的路径/118项等属于当时时点；当前计数见 audit/r4。

## 接手检查顺序

1. 从交付人取得归档及独立渠道的预期 SHA，核对外部摘要；仅同目录摘要不能认证发行者。
2. 解包到新目录，执行 verify_release 核对文件集合、内容和链接；额外文件、缺文件或摘要失败立即停止。
3. 运行 doctor core，查看 Python/Git；运行 offline_acceptance，检查30条/PARTIAL、RepoRank0条、47文件和对应源码映射。
4. 配置经过核实的 OpenSSL 3，运行 portable 单元回归。期望只跳过3项 Linux 集成；额外跳过、导入错误或负控失败不得接收为“已验证”。
5. 查看修复说明、项目专属首评/设计、未解决事项。接收人记录自身环境、结论、人员与时间；技术检查不替人签字。
6. 有可信 Loop+Linux/bwrap 时按 ENVIRONMENT 配置，另跑 full 档并保留现场证据；即便 full 档成功也只覆盖适配器/有限隔离探针，不覆盖调度器真正 E2E 或通用沙箱审计。

所有验证输出写包外新目录，运行 `python -B`，不在包内产生缓存后再假称 SHA 失效是“正常”。如确需开发，先复制工作区再修改，保留发行只读副本。

## 使用入口

- 搜索：`python3 skills/github-project-evaluation/scripts/discover.py --help`。先说明查询/来源/预算/许可，检查 robots/rate limit。`PARTIAL` 不等于无候选，COMPLETE不等于质量通过。
- 首评：`evaluate_first_pass.py --help`；只读 checkout 与明确 owner/repo，默认身份 BLOCK；获取在线身份需单独 --verify-upstream。
- 设计：按 Skill 和 `examples/markupsafe` 生成项目专属文档，用 validate_design 检查结构，再独立人审。
- 执行：审批范围/任务输入/源码/环境全部冻结后，只在外部隔离 worker 调用 native runner；不允许凭高分自动运行。

## 停止条件与故障排查

| 现象 | 正确处置 | 禁止做法 |
| --- | --- | --- |
| SHA 不匹配/多文件 | 保留现场、从可信来源重新取件 | 重算清单把污染结果洗白 |
| OpenSSL/Loop/bwrap 缺失 | doctor 输出 BLOCK；按文档补可信依赖 | 伪造引擎、吞导入错、把跳过加到成功 |
| manifest/source/命令/日志改变 | native 返回 BLOCK，新建经审批的run目录 | 强改旧binding、删除状态后重放副作用 |
| 状态坏JSON/旧schema/软链接 | 原件不覆盖，人工审阅后新任务 | 自动“修复”为成功 |
| 搜索缺页/缓存坏 | PARTIAL并留失败；新轮有界重试 | 编造第二页、把缓存说成上游实时认证 |
| 压力未批准/无独立oracle | 保持DESIGN或BLOCK | 用作者测试/退出0补业务PASS |
| 疑似隔离边界失效 | 外部supervisor停整任务、留日志 | 在宿主直接复现恶意代码 |

## 接收方需要指定的角色

维护负责人负责依赖、发行和回归；项目 owner 冻结 MUST/禁止项与运行许可；测试负责人冻结独立真值和 SLO；安全负责人批准 worker/网络/凭据/供应链边界；独立 reviewer 签收。姓名和审批记录必须由真实接收方填写，本包不冒名代签。

## 已知限制与后续

本机未提供真实外部 Loop 引擎或可用 Linux 执行环境，相关状态保持 BLOCK/NOT_RUN；没有安装或启动宿主 Docker 服务。没有执行第三方仓库代码或安装依赖；本次实际压力测试只针对自有Skill的有界离线缓存解析事务，不是第三方项目或服务器压力。缺独立发行签名与自有上游脚本再分发授权；这是交接限制，不由生成一份 LICENSE 解决。

原生 runner 的输入摘要是启动/恢复时完整性检查，不提供并发不可信写入者的原子快照防护；可写源码必须在 worker 中被冻结/只读挂载。RLIMIT_FSIZE只是每个日志文件上限，不是聚合磁盘/cgroup配额，setsid逃离进程组也需外部worker阻止。需要强安全时不得把本包当通用沙箱。
