# Sources, network fallback and cache

## Adapter boundaries

Implemented routes: `kaiyuanbang.cn/zh-cn/search.html?q=...&updated=365d&sort=stars_desc&page=N`, `reporank.net/en/search.html?q=...&updated=365d&sort=stars_desc&page=N`, `gitstar.space/search?q=...` (limited catalog), `api.github.com/search/repositories?q=...&sort=stars&order=desc&per_page=30&page=N` and `api.github.com/repos/{owner}/{repo}` (targeted verification). `--source multi` invokes all four searches; `--source both` retains prior site+GitHub behavior.

RepoRank is linked from Kaiyuanbang's public pages/robots sitemap, apparently the same publishing network: an alternate **host/language**, not an independent index. Its `robots.txt` allowed public pages on 2026-10-22; an initial English-query fetch timed out, but a subsequent bounded Chinese-query live run fetched **3 pages/49 unique repositories** with `COMPLETE` for *that requested query/host*, alongside synthetic HTML adapter tests. A later timeout must still be PARTIAL, not zero results. GitStar is an independent public HTML search with a directly observed `quant` result on 2026-10-22 (3 repositories); it has a limited catalog and no validated search pagination, therefore `coverage.scope=catalog-only` and PARTIAL even when its single page succeeds. No direct GitHub metadata verification comes from this site.

The app never requests arbitrary discovered URLs or follows redirects outside the allowlist. Public search was allowed by Kaiyuanbang/RepoRank/GitStar `robots.txt` on 2026-10-22; recheck rules and terms in the deployment environment before live requests. If prohibited, disable that adapter without bypassing restrictions. Future independent adapters need separate access checks, normalization, pagination fixtures and coverage tests. `findarepo.com/robots.txt` disallows `/api/` and `libraries.io/robots.txt` disallows `/search` (observed 2026-10-22): **do not** use those routes as fallback.

## Failover ladder

1. Try public HTTPS with a finite page/time budget. A WebFetch 403 does not prove all callers fail; direct GET may work, and a success must be evidenced by bytes/hash. A 403/429/CAPTCHA is not an empty result. Machine errors identify `HTTP_403`, `HTTP_429`, `DNS`, `TLS` and timeout without logging URL credentials. Do not solve a CAPTCHA or rotate identities to evade limits.
2. In `multi` mode try Kaiyuanbang, RepoRank, GitStar, then GitHub Search; failure is recorded as PARTIAL, not empty. Keep successful pages and provider-specific `coverage`. RepoRank may fail together with Kaiyuanbang; GitStar is independently hosted but only indexes a subset; GitHub API is authoritative for upstream metadata. Use `--source reporank`/`gitstar`/`github`/`site` for restricted fallback, stating the other providers were not queried. `--source multi` cannot return global COMPLETE while catalog-only results are included. Offline cache carries `cache=hit`/`stale-offline` and original fetch time. If all sources fail without matching cache, return PARTIAL/zero candidates; ask for exported pages or retry later.
3. For a Kaiyuanbang page export, require private `--seed-dir/.query` equal to the requested query and `page-N.html` (one file per page). It does not seed RepoRank, GitStar or GitHub. Stored metadata marks `origin=imported-direct-https-snapshot`; input may be stale or altered, not a fresh verification. Never reuse 量化 snapshots for another XXX query. Report row-count/page consistency and missing pages.

## Cache policy / threats

Store only bounded public HTML/JSON response bodies (max 1.5 MB/page) and adjacent JSON `{fetched_at,sha256,origin}` keyed by SHA256 of exact allowlisted URL. Cache directory is private mode 0700; symlink entries, oversized bodies and future-dated metadata fail closed. The digest and `origin` are **both stored in the same writable directory**, so a forged matching pair is not source authentication: offline replay adds `cache_trust=local-unverified`, and source identity stays pending GitHub verification. No cookies, auth tokens, HTTP headers, clone data or PII intentionally stored; GitHub auth, if supplied via `GITHUB_TOKEN`, is used only in-memory and never logged. Site TTL 24 h; API TTL 12 h. Stale data is usable **only** offline with a stale label. Expired online cache refetches; tampered payload fails closed offline. One run creates an immutable new output directory; preserve older evidence. Define retention/cleanup with the owner (suggest raw snapshots 7 days, summarized aggregate 30 days, signed research artifacts per project policy). Cache hit does not imply fresh upstream verification.

## Resource and security ceilings

Default max 25 site pages, up to **three new GitHub Search pages per run** (30 rows/page, prior cached pages are replayed so the next run continues from the first missing page) and up to 8 targeted repo checks; 0.45 s delay between site pages, HTTPS-only fixed endpoints, 12–15 s per fetch, no recursive detail-page crawling. Full pagination beyond each cap is intentionally PARTIAL pending a separately authorized increase; GitHub Search also imposes its own first-1000-results window. Respect remote 429 retry-after by stopping this run rather than hammering or forging another IP. Untrusted HTML is parsed as data and escaped in Markdown. Never execute code found in retrieved repositories during discovery.
