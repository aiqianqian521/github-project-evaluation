# Loop 大循环训练：跨领域架构与三条优化 demo（设计 v2）

状态：**可实施设计稿，未实现通用在线 Agent、通用安全 worker 或跨领域自我进化服务**。这份是原[发现→评估→测试→交付骨架](loop-project-evaluation-blueprint.md)的场景细化；不是三个已经运行成功的产品，也不以文档存在充当验收。量化领域进一步参照本工作区 `runtime-review/RUNTIME-STRATEGY-EVOLUTION-DESIGN.md` 和 `runtime-review/RUNTIME-LOOP-SELF-EVOLUTION-ROADMAP-20261020.md`。历史 `work_ooda/*` 是试验快照，不应作为当前部署路径。

## 1. 大循环不是无上限重试

共同目标：将「用户目的→可观察成功标准→找可复用项目/Skill→冻结版本与授权→受控实验→独立判断→错误学习→下一版」连接起来。外圈一次迭代产生**新版本候选**，内圈 Loop 的一个 Act 只做事前批准的、可定位的任务；无法证明正确时安全停止，不为凑 PASS 改标准。

```text
用户目标与权限 G0
  → 需求/领域 oracle 冻结 G1
  → 多源 GitHub/Skill/内部组件发现 G2
  → README/入口/许可/源码/测试/CI 首评 G3
  → commit/依赖/素材/数据冻结 G4
  → 独立隔离的正负功能实验 G5
  → 限额故障/容量/回归 G6
  → 盲测/人工签收/对照 G7
  → 交付或 BLOCK + 错误知识卡 G8
  → 仅审核通过后产生下一版提案 → 新 run_id 从 G0/G1 重进
```

**控制平面**：Loop 管固定阶段白名单、依赖、尝试 ID、审批与账本；LLM 只提任务拆解、选择/解释与修复建议，不自批权限。**数据平面**：带版本的授权素材/时点数据/本地漏洞靶场、冻结 GitHub 候选、无凭据只读源码和独立隔离 worker。**裁判平面**：事前冻结的领域 oracle 与反例、签署阈值、复核人；作者测试/模型自评/Loop COMPLETE 都不是业务裁判。**学习平面**：归档失败指纹（触发条件、作用域、根因证据、修复 diff、旧/新/未见反例、失效期限），RAG 仅检索提出假设，不写入当前事实或直接改变裁判。

每个 `task_id/run_id/candidate_id/attempt_id` 独立保存 task spec、许可与审批、源码/依赖/数据/模型版本摘要、原始 stdout/stderr/exit、有限资源计量、oracle 预期/实测、人工签收。正交状态为 `coverage=COMPLETE/PARTIAL`、`execution=NOT-RUN/RUNNING/INTERRUPTED/PASS/FAIL/BLOCK`、`candidate=NOT_REVIEWED/PASS/FAIL/BLOCK`、`review=PENDING/APPROVED/REJECTED`。`PASS` 仅对冻结版本、给定用途和有证据的能力成立；关键用例 FAIL 优先于 BLOCK，许可/授权/身份/独立真值缺失即 BLOCK。崩溃不覆盖旧尝试：先保留半写日志、核对副作用，再以新的 run_id/授权重试。

## 2. 优化一：短视频/AI 短剧 demo

**用户目标示意**：「有授权素材和剧情方向，自动做 60 秒短剧；角色对话自然，镜头连贯，成片可审查」。`60 秒`只是样例输入，不是系统默认门槛。用户须确认平台、受众、语言、版权范围、肖像与声音同意书、预算及发布权限；缺权利证明只准生成离线设计稿。

| 阶段 | 输入→产物 | 事前 oracle、失败与状态 |
| --- | --- | --- |
| G1 叙事约束 | 素材清单/创作方向→人物卡、冲突/转折、台词语气与镜头时长清单 | 用独立标注集区分「直白对白」「合理冲突」「无新增未授权人物」；脚本编辑独立盲审；LLM 自称好看不算通过 |
| G2–G4 组件选型 | 查分镜、文生图、配音 TTS、音画合成和审核工具→每类冻结 1–3 个候选 | 来源不全 PARTIAL；许可、模型权重/素材再分发与调用成本未查 BLOCK；可直接复用合适组件，不重复手搓 |
| G5 资产生成 | 经批准的脚本→镜头表、图片/片段、配音、字幕及合成预览 | 冻结 seed、prompt、模型/工具版本和素材 ID；空音频、角色外观漂移、场景缺失、字幕不对齐需负控；每层失败可单独重做而非重放已发布动作 |
| G6–G7 质量裁判 | 冻结预览→镜头与剧情对应矩阵、声画同步/字幕误差、人工盲审与权利审查 | 两名或以上独立评估者按事前量表评分并检查一致性；短样片不得外推全集质量；容许重试次数/成本与接受阈值由用户签署，未签即 BLOCK |
| G8 发布 | 签收预览→离线成片和可追溯素材包 | 默认不自动发布；授权与平台审核通过后再明确放行；历史创作失败只允许作为下一稿提示，不覆盖审阅原始记录 |

**本 demo 迭代点**：记录「对白生硬/时长溢出/角色脸变/音画错位/侵权风险」为不同错误类，定位到脚本、图像、TTS 或合成节点，仅修该节点并回放受影响镜头与整片一致性。不能因为局部重拍使未经审查的旧镜头自动通过。候选功能测试的负例包括素材无授权、单次生成面貌矛盾、TTS 文案与字幕不一致、盲审人评分分歧；无权利证明始终 BLOCK。

## 3. 优化二：防御性漏洞研究 demo

**用户目标示意**：「分析公开补丁和历史缺陷模式，在获授权本地靶场检查类似风险并给出修复证据」。只允许有书面范围、指定仓库/版本/本地环境的防御性工作；**禁止将此流程变成未授权公网探测或自动利用**。

| 阶段 | 输入→产物 | 事前 oracle、失败与状态 |
| --- | --- | --- |
| G1 范围与真值 | 授权范围、公开公告/修复提交、前后版本→假设、构建身份与边界 | 来源不明、漏洞描述未经核实、缺影响版本时为 HYPOTHESIS/BLOCK；RAG 历史案例只提出待检假设 |
| G2–G4 复用工具 | 查询公开源代码/测试器/静态审计工具→许可/依赖/供应链清单、只读补丁差异 | 模型不得从不可信 README 获取执行指令；冻结 commit 和测试输入；受控靶场无公网出口/凭据 |
| G5 对照实验 | 同一规范化输入在**本地**前/后两个构建运行→退出、回归与资源日志 | 前版本正对照须确证实验能识别风险，修复版负对照须证明问题消失，正常输入还需不退化；正对照未生效则 BLOCK，不许报补丁有效 |
| G6–G7 故障与复核 | 限额边界测试与独立复核→根因/补丁审阅、误报/漏报卡片 | 对缺失隔离、权限越界、误触外部地址立即停止；双人复查错误归类及披露边界；没有独立复核不报“发现新漏洞” |
| G8 学习与交付 | 经批准的审计摘要→补丁回归规则、来源与失效版本 | 只存脱敏/经授权的样本及反例；风险结论与发行版本绑定，修复建议须另走代码评审/发布；不自动提交或公开利用材料 |

**本 demo 迭代点**：知识库以漏洞类、受影响构建、补丁摘要、已证实反例和失效条件索引；匹配历史案例仅产生新假设，新版本必须重新建靶场、取新正负对照。对「静态工具报错却无可复现证据」「修复版回归功能坏掉」「历史检索指向旧版」分别给 FAIL/BLOCK/过期拒检，不把扫描告警当可利用性证明。

## 4. 优化三：量价/指标→回测→模拟盘 demo

**用户目标示意**：「用缠论、价量/VPA 等生成信号，先研究再纸上交易；规定什么时候下单、禁交易和退出」。这里不提供真实交易建议。各币种、交易所、时间框架、成本和合约杠杆必须单独建版本；7/14/21/30 天亏损触发**研究工单**，不能直接让 Agent 改生产策略。

| 阶段 | 输入→产物 | 事前 oracle、失败与状态 |
| --- | --- | --- |
| G1 数据时点 | 带采集时间、发布/修订时间的 OHLCV/盘口/费率和数据缺口→可用性账本 | 每个决策时刻只取当时可用数据；延迟、停牌、退市、复权和合约换月明记；未来修订流入特征即 FAIL，缺谱系则 BLOCK |
| G2–G4 组件/策略冻结 | GitHub 回测器、数据源、指标/过滤器/仓位/止盈止损模块→冻结代码、版本参数、费用规则 | 静态星数/收益截图不能证明防未来数据；每币/每指标页面附 MD、参数来源、filter→入场→退出 Mermaid 流程及适用日期；未审的 README 不得执行 |
| G5 时间顺序实验 | 冻结训练/验证/未见测试窗口→逐笔候选信号、禁单原因、实际可成交性模拟 | 信号时间 < 委托时间 ≤ 可能成交时间；缺量、涨跌停/滑点、手续费/资金费与拒单都应计入；账本区分“信号”“模拟报单”“成交”，禁止伪装历史成交；独立重算未来数据/止损触发负控 |
| G6 韧性及压力 | 局部断线、重复 K 线、延迟、价格跳空、订单部分成交→风险/恢复日志 | 以 bar、信号和订单数定义负载，预先签并发/时间/内存及失败阈值；网络失联、延迟行情与超额杠杆应触发禁止开仓/熔断；不连接真资金测试 |
| G7 盲测/对比 | 冻结最终未见时间窗及基线→费用后收益、最大回撤、尾损、拒单率与样本统计 | 参照预先冻结的对照策略和多币多期窗口；全体试验（含失败）记账，避免只呈现最优参数；研究窗口不能反复调参后再叫“未见”；指标不达阈值 FAIL，样本不足 BLOCK |
| G8 纸上盘/审批 | 用户确认策略和风控上限→只读观察或纸上单账本 | 7/14/21/30 天亏损只是候选假设触发，参数重训/改代码需新 run_id 与新 holdout，回滚先于发布；**绝不自动接真实交易 API 或真实资金** |

**本 demo 迭代点**：对于一次亏损，先分解数据缺口、信号误判、filter、止损执行与成本模型；每次只改可归因的层并锁定其反例。对 ETH/BTC/SOL 不用一个参数蒙混所有币：资产/周期/标的/数据版本为组合键，各自保留参数、适用条件和失效日期。回测绿灯不替代纸上盘成交回放，更不自动准入实盘。

## 5. 训练/进化协议：如何不把自己训练成只会报绿灯

1. **冻结目标与裁判**：先用用户需求生成有签收的 `task-spec`、能力 MUST、不可接受错误、业务 oracle、许可/执行边界。冻结 `baseline`、公开调试集与**不参与修补的 holdout**，标记每项证据来源与签署人。无独立真值的任务可以做资料整理，不得训练出「验收 PASS」。
2. **基线轮 R0**：Skill/无 Skill、同模型/数据/预算/权限对照；记录所有成功、FAIL、BLOCK、未运行和费用。把每条失败拆成「发现漏召回、目标适配误报、环境依赖失败、业务行为失败、判官错误」而不是一句“模型不好”。
3. **候选轮 Rn**：Agent 只提出 Skill/插件/工作流的小范围 diff、预期修复的错误指纹及可能退化；不可改隐藏集、审阅签名、历史账本和授权票。代码/提示词版本化、哈希；开发集先测已知反例，再用未见仓库/素材/历史市场窗/前后补丁重新反证。
4. **晋级/回滚**：已签署的关键能力不能退化、误放行率不能增加、资源/成本不能越界；任一关键用例 FAIL、权限缺失或测试器自证即停止并保留旧版。跨域的指标独立，不能靠视频好看补交易穿越、靠作者测试绿灯补靶场漏洞正对照。独立审阅决定版本晋级；回滚至最近经验证版，不覆写原证据。
5. **错误知识治理**：经验卡包含来源/版本/时间、复现步骤（去敏）、触发边界、否定例、修复 diff、适用领域和到期/失效条件；RAG 命中后先核对当前版本和环境，再生成实验，不自动晋升为规则或修改历史记录。

## 6. 当前可用入口与尚未完成的交付

- **已部分实现**：`skills/discover-open-source-projects/SKILL.md` 可做有界多源候选、静态首评、来源缺口及离线 Loop 阶段；`skills/design-project-tests/SKILL.md` 可做项目相关功能/压力**设计**与基本结构校验。当前本地验签只说明特定公钥对证据字节签名，不能自己签署自己。
- **未实现通用版**：G0–G8 在线分派 DAG、对任意 GitHub 仓库安全执行的通用 worker、可独立认证的事前签发/撤销、视频盲审系统、漏洞靶场自动审计、量化无未来数据全链路/纸上盘交付、自动更新 Skill 后冻结 holdout 的晋级服务。三个 demo 均为设计，不是成品。
- **下一验收顺序**：先选择一条场景由用户提供合法素材/数据/授权和独立 oracle → 冻结至少一个可复现正反例 → 在独立 worker 小规模实现一条 G0–G8 路径 → 与基线/未见样本对照 → 人审签收；再让 Loop 将成功的、有证据的局部能力包装为可复用 Skill。不能先开放未知仓库执行或真实交易，再补安全证据。
