# Discovery → static review → test design/authorized execution

This package contains `discover-open-source-projects` (candidate discovery and first pass) and `design-project-tests` (functional/load design, plus separately authorized execution). Treat source metadata, a frozen local checkout and actual execution as **different trust levels**; neither Skill automatically certifies a project.

1. Read the original `candidates.json` (`project-discovery.v1`) and `SHORTLIST.md`. Carry forward `query`, provider `coverage`, `PARTIAL` errors and the selected canonical `owner/repo`; do not silently fill a failed page from popularity or another provider. The candidate row is a lead, not an approval or a verified checkout SHA.
2. Read `FIRST-PASS.json` (`project-first-pass.v1`) and its human assessment. Check `expected_repository`, `local_commit`, `evidence` file hashes, `blocking_gaps`, `goal_fit` and `identity_gate`. A cached/API *repository* metadata hit does not verify the commit. If needed, rerun first pass with `--verify-upstream`; GitHub 403, origin mismatch or missing commit keep `identity_gate=BLOCK`.
3. Run `design-project-tests` in **DESIGN** mode to produce the project-specific `FUNCTIONAL-TEST-DESIGN.md`, `PRESSURE-TEST-DESIGN.md` and `TEST-HANDOFF.md`. In the handoff cite discovery/first-pass paths, pinned commit, unresolved licence/source/reproduction risks, every MUST → independent oracle → F/P case ID and a separate owner for each blocker. Run `scripts/validate_design.py` and manually challenge its semantics. If identity or authorization is missing, design may continue but all execution cases remain `NOT-RUN/BLOCK`.
4. For **EXECUTE**, obtain a separate scope/stop budget/independent oracle approval. Use an actually restricted worker appropriate to the project; `discover-open-source-projects/scripts/run_isolated_cases.py` only supports short, shell-free, no-network, no-host-writable probes on supported Linux and always emits `deployment_test_gate=BLOCK`. The server-origin test Skill's native Loop runner is **not** automatically sandboxed just because it stores logs: never pass unknown GitHub commands directly to the default unsandboxed Loop process. Web/UI, distributed services, long load, network access and financial execution need separately designed isolation and authority.
5. Preserve raw stdout/stderr/exit and source/spec/config/environment hashes; run `scripts/validate_execution.py` on authorized execution artifacts. Record actual business-oracle evidence and review separately. For failures follow `error-learning-loop.md`: original incident → bounded diagnosis → reviewed fix hypothesis → old and unseen regression → version-scoped lesson. An exit code, log checksum, model opinion or Loop `COMPLETE` cannot stand in for acceptance.

The two Skills can be installed together. Install **only one** directory whose frontmatter says `name: design-project-tests`: the package's `skills/design-project-tests` is the server-origin design+execution version with this handoff/error-learning addition; the local older design-only copy is not a second installable variant in this package.
