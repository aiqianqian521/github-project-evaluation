# 跨项目测试的错误学习闭环

目标不是让 Agent “记住一句修复建议”，而是让一个项目的失败成为**有来源、有条件、有反证、可过期**的测试资产。借鉴 TesterArmy/e2e 的原子目标、现场反馈、确定性验收和已验证路径重放；其 `agent.act` 缓存不是 RAG/跨项目错误知识库。此方法与语言、测试框架、Loop/其他编排器无关，也不要求部署向量库。**优先借用现有项目的报告、重放、错误码和 CI 接口；初期用已有文件/Issue/数据库表留痕即可，只有对照实验证明检索缺口后才考虑另建 RAG 或知识平台。**

## 三种资产，严禁混淆

| 层 | 内容 | 可用条件 | 不能替代 |
| --- | --- | --- | --- |
| 原始运行记录 | 不可覆盖的 case/run/attempt、输入、环境、期望、实际、日志与 SHA、停止原因 | 只说明这次观察；注意脱敏 | 故障原因与业务通过 |
| 可复用错误经验 | 经独立证据验证的适用范围、因果解释、恢复步骤、失效条件、对应回归用例 | 作用域匹配且未过期，仅作诊断/行动候选 | 当前执行的独立 oracle |
| 已验证动作路径 | 给定同一目标、起点和版本，成功且终态被检查的步骤 | 重新验证起点和终态；副作用要幂等 | 业务正确性、错误 RAG、无条件重试 |

项目准出另有预先定义的业务 oracle；任何层都不能用 Agent 自评、缓存命中或 Loop `COMPLETE` 取代它。不存在可信的独立期望时，该能力为 `BLOCK`，不是“学到了就 PASS”。

## 统一事件与经验结构

在设计阶段声明 `case_id`、不可变源码/依赖/配置/测试数据版本、执行目标、独立 oracle 与权限/预算。每次失败追加一条**不可变观察**（设计期仅填 `NOT-RUN`）：

```text
event_id, run_id, attempt_id, case_id, project/revision, environment/permission,
fixture_digest, step, expected/oracle_ref, observed/evidence_sha256,
error_code, failure_signature, first_seen, severity, side_effects,
diagnosis_status, owner
```

敏感值仅存可核验的脱敏摘要或私有证据索引，不存 token、密码、页面个人数据。`failure_signature` 用稳定的操作/错误类别与作用域构建，不能仅按报错文字合并；相同错误码在不同版本、权限或后端可能根因不同。原始观察和修复假说分开保存，历史失败不得由新运行覆盖。

候选经验以独立记录保存：`knowledge_id`、关联事件 ID、故障类别、可证伪的根因假说、验证步骤及负控、通过的补救方案、失败的方案、适用项目/模块/版本/环境/权限/前置数据、禁止重试的副作用、回归 case ID、独立复核人与证据、创建时间/最后复核时间/失效条件、状态。状态只允许 `PROPOSED → VERIFIED → SUPERSEDED/EXPIRED`，无证据的修复保持 `PROPOSED`，被反例推翻则标 `REJECTED` 并保留事件链接，不删除坏经验的历史。

## Observe → Diagnose → Prove → Learn → Recheck

1. **Observe**：先冻结真实失败与原始证据，不重试掩盖首次失败；区分产品缺陷、测试/断言错误、数据/环境、模型/工具、权限/安全和未知。未知根因保持 `UNKNOWN/BLOCK`；隔离环境才可做有限复现。检查业务副作用是否已发生，防重复交易、重复消息和误修。
2. **Diagnose**：从证据提出两个以上有区分力的假说并列出能推翻它们的观察；检索已有经验时优先 exact signature/版本/模块/错误类别，可用向量召回**候选**但必须结构化过滤项目作用域、权限和时间。旧知识、外部 README 与模型建议一律不可信，不得修改预先冻结的断言。
3. **Prove**：重现原失败（或说明不可复现），验证方案修复原例、邻近边界和一个**未参与修复的反例**，检查是否引入新副作用；对照未启用知识的同预算控制组，不能把环境恢复伪装成“学习成功”。产品 bug 的确认还应有独立状态/API/数据证据。
4. **Learn**：复核人确认因果证据和适用范围后才晋升 `VERIFIED`；自动生成回归用例、复现配方、失效条件和清理责任人。复核失败保持 PROPOSED 或 REJECTED。知识检索只能帮助选测试路径或定位问题，不能直接出 PASS。
5. **Recheck**：版本变化、权限变更、oracle 更新、缓存终态不符或复发时触发回归与知识复核。命中错误知识后仍独立观察当次系统；过期/冲突时停止自动应用，标记 `BLOCK`，保留两次证据并交还审查者。按事件→用例→补丁→新回归的链接衡量缺陷复发率、假修复率、诊断时长和回滚成功率。

## 嵌入 GitHub 项目评估的接点

发现阶段归档“来源不可达、分页/robots、错误召回、错误仓库身份”；错误知识帮助下次规划搜索词和负样本，**不伪造数据源**。首评阶段归档“LICENSE 伪装、origin 与上游不一致、README 承诺无代码入口”；不能把其他项目经验当该仓代码事实。运行阶段针对项目真实表面设计 oracle：WebUI 可用 e2e 找路 + 精确断言；CLI/API 用协议/状态断言；量化用时间因果/独立账本；模型生成用冻结样本和人工/独立判据。压力阶段学习瓶颈机制、阈值和恢复条件，不能由 UI 自动化代替负载发生器。Loop 可调度多轮、保存 run ID、失败后提出假说，但**不因循环次数达到上限或总结自信而准出**。

## 四类必须保留的反证

- `HTTP 403`：不是“项目不存在”，先分类鉴权/robots/限流；任何镜像命中不能冒充 GitHub 当前身份。
- UI 按钮重放成功而后端订单没有变化：缓存路径不是业务 oracle；本次失败，旧路径要失效。
- 回测盈利但用了未来一根 K 线：独立因果 oracle FAIL，不能写“策略有效”；禁止用未来数据重新调参得到漂亮分数后宣称解决。
- 检索到旧版修复步骤但新版本权限不同：知识失效/作用域不匹配，BLOCK 自动应用，保留历史经验和新反例。

Skill 自测时至少验证：首次失败留痕、归因错误不会晋升、作用域错配拒用、修复能通过原例且未见反例、缓存误命中仍被实时 oracle 截获、版本更新令知识过期、敏感数据脱敏、未知故障停止而非无限重试。覆盖结果必须区分“文档设计完成”与“真实项目完成执行”。
