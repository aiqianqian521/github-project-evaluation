# 架构与演进路线（2026-10-22）

## 组件边界

`Intent`（领域、角色、许可/语言/地区、执行权限）→ `Planner`（同义词、反例、来源与页预算）→ `SourceAdapter`（逐页抓取）→ `Normalizer`（仓库 canonical owner/repo）→ `EvidenceStore`（源 URL、时点、body SHA、错误）→ `Ranker`（候选，不是验收）→ `Reviewer`（拿 commit 再做二次测试）→ `Report`（短表、拒选原因、BLOCK、复测条件）。Loop 是可靠调度/追溯与任务分步组件，不代替检索源、授权判断或独立 oracle。

当前已实装的适配器是开源榜中文搜索、关联运营的 RepoRank 英文搜索、独立但只覆盖有限目录的 GitStar HTML 和 GitHub REST Search/Repos。`multi` 按 `owner/repo` 合并，记录逐源 `coverage`；GitStar 的 catalog-only 天然使 `multi` 保持 PARTIAL，不能因为 HTTP 200 当全网覆盖。Ranker 只是可重复启发式；Agent 人工角色归类和语义精排必须标注模型判断并保留原始数据。每加 adapter 要明确 robots/条款、分页上限、回归快照、限速和降级；抓取失败不能退回模型臆测。

## 分页、缓存、身份

- 开源榜基于首页 `total` 与页码枚举，检查实际唯一仓库总数；缺页、结构变化、重定向、重复记 PARTIAL。快照分页显示 13 页 244 个项目；稍后在线页第 13 页增加 1 个，245 项，两次独立记录不能被“合并成”同一时刻。
- GitHub REST Search 总数可能超过单轮 3 页预算，必须输出 PARTIAL 和 `remaining`。保持同一 query/sort/per_page 的缓存键，下一次使用已缓存页并继续后续 3 页；至多 `max_pages=25`，超限需要 owner 批准提高预算或切分检索条件。Search 服务自身前 1000 条窗口不能标完整；即使请求页数吻合，`total_count` 与实际唯一 ID 不一致也必须 PARTIAL。按 `owner/repo` 去重，迁移、大小写、fork 的归属不能靠名字推断。人工确认 redirect 再更新 canonical ID。
- 只缓存公共 HTML/JSON body、时间、SHA、来源，站点 TTL 24h、API 12h；原始查询可能敏感，私有目录 0700，交付前按数据政策脱敏。缓存重放不抹掉原在线证据；Loop 快照使用独立目录。设定保留周期与上限（建议原始公共快照 7 天，汇总 30 天，正式审计由项目政策决定）。

## 错误与中断

- 无法联网：说明是 DNS/TLS/403/429/超时中的哪类（安全起见机器账本默认只给异常类型，详细上下文用脱敏运维日志），切换其他来源或离线快照，最终 PARTIAL/BLOCK。公开网站不可访问不等于项目不存在；不能轮换 IP/伪造身份规避限制。
- 数据问题：HTTP 200 空结构不是空结果；`total` 与已解析唯一数不匹配、GitHub `incomplete_results`、页超过预算、哈希污染均阻止 COMPLETE。缓存哈希仅证明本地完整性，缓存与元数据同目录时无法提供外部来源认证，离线记录 `cache_trust=local-unverified`。记录受损页重试条件；不删错页凑整。
- Loop 中断：单阶段开始前写 `INTERRUPTED`；断电/kill 后**不自动重做网络抓取**，先核对是否已写部分文件，再用新运行 ID、预算和快照重新执行。一个阶段前轮 FAIL 不因后轮 snapshot PASS 而洗白。

## 六级验收门禁

1. 目录结构/frontmatter 校验，明确项目任务成功判据与检索预算。
2. 离线单测：协议白名单/URL 重定向/HTML 注入/解析/分页/去重/缓存哈希/空缓存/未知字段/多源计数和续页负控。
3. 本地受控性能：只读本地快照重复解析，记录真实行数、耗时、峰值 RSS；绝不向 GitHub/开源榜施压。
4. 实网功能：在隔离账户和工作树下抓完约定页数；保留原始 HASH、所用网络环境、每页行数、口径时间；网络失败留红灯。
5. Loop Act：真实调用在线/快照/空缓存负控三个阶段并保存每轮原始输出和 DB；复查重试去重、断点状态、跨阶段失败传播；Verify 不等于项目验收。
6. 二次评估：对 3–5 个跨领域仓库分别 freeze SHA，真实 build/test/风险 oracle/许可/安全/压力；另经独立审核批准才写特定项目 PASS。此步骤在没有克隆范围或业务 oracle 时保持 NOT-RUN/BLOCK；不能以 Skill 测试通过代替。

## 下一迭代 P0 / P1

P0：更多语义召回（中英同义词多查询）和按角色的覆盖度约束；结构化语言/许可证/更新时间过滤要区分“未验证”和“真不满足”，避免 site 字段当上游事实；对仓库迁移与重复页增加灰度负控；以有证据签名的 reviewer 决策回填，而非修改原始结果。P1：第三方榜单独立 adapter（先查 robots/条款）、查询分片与增量调度、跨查询 dedup、签名的缓存保留/删除策略和二次评估仓库拉取接口。跨项目的“自我进化”须用冻结训练/测试集和独立 holdout，对差异审计后才修改 Skill；不允许边看答案边调权重。
