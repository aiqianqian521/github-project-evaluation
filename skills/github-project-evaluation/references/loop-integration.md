# Native Loop adapter: explicit integration, no simulated Act

The `scripts/loop_discovery_runner.py:DiscoveryRunner` is an `agent_prompt` TaskRunner using Loop's own `TaskInput/TaskResult`. It actually invokes the parser/cache and records `evidence/{stage}/candidates.json`, `SHORTLIST.md`, SHA-256, page counts and `discovery-state.json`. Stages are bound to one frozen signal `signal_pattern` per `--once`: `online`, `snapshot` (query-bound saved HTML), `negative` (empty-cache offline fault). Snapshot imports use **separate** `snapshot-cache`, never overwrite online raw bytes. `online_row_delta` records changing upstream counts without calling stale snapshots current. Loop may retry the same Act: an attempted stage returns its prior result **only while recorded config/runner/parser, stage inputs, cache contents, output hash and prior stages still match**; any mismatch returns an error without refetching or overwriting the old record. Malformed journals are rejected intact. A crashed stage is `INTERRUPTED` and never replayed silently; use a fresh tree for retest. A recovered snapshot can succeed while the online stage remains PARTIAL; the aggregate business verdict stays rejected. This only hardens this adapter's `--once` stage replay: it does **not** certify Loop core checkpoint `--resume`, externally witnessed history, or side-effect-safe retries. `Verify` is never source-code approval.

Config: `LOOP_DISCOVERY_CONFIG=<absolute-config.json>` pointing to `{root,query,max_pages}` with preexisting isolated root, `root/snapshots`, `root/evidence`; `PYTHONPATH=<skill>/scripts:<loop-engine>`. Use the bundled `references/loop-config.yaml` as a template and put per-stage signal JSON inside a private `projects/discovery-task/data` root, with config's `runtime.root` pointing there. Use Loop's `orchestrator.py --config ... --signals <single-stage-file> --once`, **not** `run_loop.py`. The Loop config includes an explicit contained backtest script to satisfy its composition root but the `agent_prompt` branch performs discovery instead. No internet requirement for snapshot/negative stages; online access is attempted only against the bounded allowlist. A test project path ending in `discovery-eval` caused the current Loop Guardian's keyword rule to reject its benign contract probe (`eval` inside a path); keep the failed doctor log and treat that as a Guardian false-positive, not as a passing safety test. The `discovery-task` template avoids this unrelated naming collision; fixing Guardian's argv/token parsing belongs to Loop-dev maintainers.

Trust boundary: the adapter executes Python in Loop's unsandboxed agent process, not inside a security sandbox or Loop's external-command ExecGate. Run only a reviewed Skill and task config under a non-root account with private HOME/TMPDIR/project paths. Never pass the user's credentials in Loop signals, logs or manifest. Do not use Loop to circumvent site 403. Only the human reviewer may sign the second-pass repository verdict.
