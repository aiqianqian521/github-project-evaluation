# Output and traceability contract

`project-first-pass.v1` adds `identity_gate=PASS/BLOCK` and `upstream_commit_verification` (status VERIFIED/NOT_REQUESTED/BLOCK, reason on failure). Only a fresh, allowlisted GitHub commit endpoint response whose SHA matches the local clean HEAD and whose declared origin matches `owner/repo` yields upstream commit VERIFIED. This only verifies commit existence/identity, not source behavior, artifact authenticity, license approval or permission to run code. A discovery candidate, local origin or offline cache alone cannot clear the gate; the static `triage` remains separate.

Machine result `project-discovery.v1`: `query`, `source_mode`, `status` COMPLETE/PARTIAL **for requested bounded sources**, `coverage` keyed by provider with status/pages/rows/scope where applicable, `rows_seen`, `provenance[]` with `url`, `sha256`, `fetched_at`, `cache`, `origin` and `cache_trust=local-unverified` for local cache hits, `errors[]` with provider/page/reason, deduplicated `candidates[]`, `shortlist[]`, `shortlist_min_score`, `acceptance=NOT_REVIEWED`. Optional `goal_constraints` (`language`, `role=library`, `concept_any` with up to eight user-supplied alternatives) adds per-candidate `goal_hint.status=MATCH_HINT/UNKNOWN/REJECT_HINT`, explicit reasons and `role_review_leads`: only MATCH_HINT items at or above score cutoff enter auto shortlist; low-score MATCH_HINT items are **manual leads**, never silently promoted. Missing language, absent library keyword, or no bounded-summary concept keyword is UNKNOWN, not proof of mismatch; known C++ versus requested C is a reject hint. Role and concept metadata keywords are not proof of source behavior; include unverified/omitted candidate counts when reporting precision and rerun synonym queries to improve recall. The preliminary shortlist cutoff is 50 except for directional English `<source>-to-<target>` queries (40 to retain low-popularity research leads); no cutoff represents domain quality. Directional matching requires an ordered local conversion phrase, not unrelated occurrences of both words; if omitted capabilities are important, expand synonyms and record recall gaps. A cache data/hash pair is not source authentication. GitStar catalog cannot claim exhaustive coverage: it always yields PARTIAL if selected. Exact `owner/repo` fallback after GitHub Search failure may add `github-direct`/`scope=exact-only` metadata with `github-api` still PARTIAL and original errors retained; offline cached metadata may support a lead but `github_verified=false`. It never confirms a commit SHA or upgrades partial Search to COMPLETE. `COMPLETE` is collection status, not evidence that a candidate exists upstream. Each candidate has canonical owner/repo, display title/summary, category/language, site stars (potentially from either related mirror, not additive), upstream stars if checked, archive/fork/license/push fields only if known, sources, detail URL, score/rationale, and `review_state=PRELIMINARY_ONLY`. When site and GitHub metadata exist for the same repository, ranking uses GitHub name/summary/language (including explicitly unverified cached GitHub data); the earlier site wording is retained as `site_title`/`site_description` for audit, not mixed into ranking. If only a site row exists, its summary remains a site claim, not verified upstream evidence.

User-facing `SHORTLIST.md`: exact query/date/sources/pages covered, recommended candidates *by role*, reason for inclusion/exclusion, URL and snapshot/verification state, unknowns, next second-pass actions. Example:

| Role | Repo | Evidence | Why shortlisted | Unknown / blocker | Next action |
| --- | --- | --- | --- | --- | --- |
| Trading engine | `owner/repo` | public search page, observed UTC, hash; upstream metadata if available | explicit backtest/execution scope | license text, lookahead, activity not checked | freeze commit and run isolated oracle |

If blocked: show `PARTIAL`/`BLOCK` as a first-class outcome, attempted sources, failure type, missing pages, cache age and exact recovery action. No fabricated stars or invented GitHub endorsements. Scoring is a search triage tool; optional hand-curation is documented separately and must not silently mutate the machine record. Substantive claims in final user-facing lists need direct evidence URLs rather than just relying on an aggregator snippet.
