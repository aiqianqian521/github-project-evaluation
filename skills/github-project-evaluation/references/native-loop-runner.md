# Loop-driven native project testing

For r3, first read [runtime-r3.md](runtime-r3.md): legacy journals are incompatible, recovery checks input/log bindings, and stage completion is not whole-plan completion. The v4 companion configuration filenames mentioned later are historical external artifacts, **not bundled ready-to-run files**; obtain and review the real engine/configuration before attempting that historical invocation.

Use `scripts/loop_native_test_runner.py` as a **trusted** `agent_prompt` TaskRunner. First freeze the ZIP/hash, explicitly authorize the test scope, clone the tree under `the legacy internal test server`, create a non-root user and isolated HOME/TMPDIR/SQLite, and predeclare which commands and resource/time budgets are safe. Never allow untrusted manifests/argv, `sudo`, network endpoints, production transactions or destructive tests. This adapter directly invokes subprocesses: Loop's `ExecGate` is **not** in that call path; restrict manifest write permission and audit each command before launching. Do not mistake this for sandboxing.

Set `LOOP_TEST_MANIFEST` to an absolute JSON file containing `project_root`, `evidence_root`, `home`, `scratch`, `max_total_seconds`, and ordered `stages` (`id`, `cwd`, absolute-executable `argv`, `timeout_seconds`). `evidence_root`, `home` and `scratch` must already exist; `cwd` must remain within project root. The caller sets `PYTHONPATH` to the Skill `scripts/` directory so Loop can import `loop_native_test_runner.NativeProjectTestRunner`. The runner does not forward API keys or arbitrary environment variables to test children. Send **exactly one signal with `signal_pattern` equal to the requested stage id** per Loop invocation (`--signals` with a per-stage input file); Loop may retry a failed Act inside the same round, and that retry must return the recorded failure **without advancing to another stage**. Stage order is fixed, and each attempted stage is journaled once in `native-test-state.json` with raw `*.stdout`/`*.stderr` and SHA256. A stage claimed as `INTERRUPTED` after process death is **not retried automatically**; inspect/clean the isolated tree and authorize a fresh run instead. Locking prevents concurrent duplicate stages.

Review `native-test-state.json` plus the original command outputs, project gates and DB/output invariants **independently**. A later PASS does not erase a previous failure; `TaskResult.status=error`, `business=rejected` and `project_verdict=FAIL` propagate cumulative failures. A stage timed out or lacking its exit status stays FAIL. After staged native checks, only execute separately authorized HTTP/load/security probes with signed thresholds and an independent oracle; write `TEST-EXECUTION.json` and run `validate_execution.py`. Loop Verify, `--once` process exit and structural Skill validators are not business acceptance.

For the frozen Loop-dev example, the companion `loop-config.yaml`, `server-manifest-final.json`, `native-test-signals.json` and `gate-only-signals.json` live alongside this Skill in the v4 handoff. Copy the first signal into `<isolated-project>/projects/native-project-test-v4/data/native-test-signals.json` and the second into `gate-only-signals.json`; copy the Loop config into `<isolated-project>/loop-engine/config.native-v4.yaml`. From `loop-engine/`, with isolated `HOME`, `TMPDIR`, `PYTHONPATH=<skill>/scripts:$PWD` and `LOOP_TEST_MANIFEST=<absolute-manifest>`, invoke `python orchestrator.py --config config.native-v4.yaml --once`. After reviewing stage one, invoke `python orchestrator.py --config config.native-v4.yaml --signals <absolute-project-path>/projects/native-project-test-v4/data/gate-only-signals.json --once`. **Do not use `run_loop.py` as the CLI**: it imports and exits without executing the test. Both rounds return nonzero when the frozen project has known defects. Keep the original run logs and never reset the runner journal in place.
